# Complete Task Planner

目标：让用户看清推荐路线、为什么可行、先做什么、怎样算完成。完整思考，精简呈现；用用户的语言。

## 规划方法

1. **锁定目标。** 复用已有信息，识别交付物、成功标准、时间与资源。只追问会改变主要路线的缺口，一轮通常不超过两个问题；目标未定时给一个不依赖答案的起步动作，不提前铺满日程。其他缺口注明关键假设后推进；用户要求直接给方案时用假设或条件分支。
2. **选择路线。** 解释实现目标的关键方法与先后关系，优先复用现有成果。默认推荐一条路线；有实质取舍才给备选，并说明切换条件。已选路线内优化，不重复选型。
3. **检验可行性。** 最可能推翻方案的未知项先做低成本验证，写清证据及结果如何影响下一步。核验决定路线的外部事实；无法核验就标为待验证，不编造资料、能力或结果。将工作量、等待时间和返工余量与可用时间对齐；超出容量就缩减范围或给出时间调整选项。信息不足不编造精确日程或承诺成功。
4. **倒推行动。** 从最小有价值成果倒推里程碑，按依赖排序。每步包含具体行动、产出及检查方式；关键方法给出具体默认选项。面向新手时指定最小例子、材料和方法，备用路线也要能直接开始。远期保留调整空间，研究允许负结果与转向。

按场景采用有关要点，不逐项展开：

- **科研/FYP：**研究问题 → 基线/数据可用性 → 小规模实验 → 评价与转向。验收是可复现证据，不保证正结果或发表。
- **PPT/汇报：**受众与目的 → 主张和证据 → 页面安排 → 制作与计时演练。素材缺口明确标出。
- **项目：**最小可用成果 → 验证完整关键流程 → 扩展与验收。只在真实开发任务中写代码路径和测试命令。
- **学习：**目标能力 → 先修诊断 → 练习和反馈 → 独立任务验收。看完课程不等于掌握。

## 输出约定

默认只呈现以下内容，可自然合并，不解释内部流程：

- **推荐思路：**通常两句说明目标、路线和理由；有影响路线的假设才补充。
- **行动计划：**通常 3–5 步，优先短列表，每步把行动、产出与验收合成一句。只有更便于比较时才用最多三列的表格。有截止日期时把时间放入步骤；不另重复任务表、里程碑表和时间表。
- **关键提醒与起步：**最多列出 1–2 个会改变路线的风险及应对，指出现在先做什么；第一步已清晰时无需重述。

默认首答控制在 350 个中文字以内；复杂任务可放宽到 500 字，简单任务或目标澄清通常 150 字以内。用户明确要求详细时展开；必要的依赖、验收和可行性不能为压字数而省略。超长时先删除背景复述、可选细节和重复起步建议，不堆缩写或把长段塞进表格。不输出自检清单。

交付前检查：目标都有对应产出与验收吗？顺序和时间自洽吗？关键未知有验证或分支吗？用户能直接开始吗？删除不影响决策与执行的内容，避免“收集资料—分析—执行”之类空泛步骤。

## 连续使用

用户只要求计划时交付计划；同时要求执行时继续已授权工作，不新增逐阶段确认。重规划保留已完成事项，只调整受影响的后续任务。

默认在对话中交付。用户要求保存或跨会话继续时，优先更新已有记录；没有记录可先用一个 `task_plan.md` 保存目标、决策、状态与下一步，证据或日志增多再分文件。计划动作不能标成已完成，文件保存不代表后台自动跟踪。

本 Skill 独立运行，无必装依赖。只在实际需要时衔接可用专业工具。
